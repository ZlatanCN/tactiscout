# 在工作台和报告中说明数据范围

Type: task
Status: resolved
Labels: ready-for-agent

## Goal

让用户在开始调查前和阅读报告时都能看清当前数据源的时间范围、候选池边界，以及哪些结论不受这份数据支持。

## Context

最近增加了 Sportmonks 当前赛季球员 provider，也保留了 StatsBomb、Wyscout、SkillCorner 历史数据与虚构演示数据。现有界面显示数据源名称，但没有统一解释其时间属性和覆盖限制。用户无法仅凭来源名称判断当前看到的是现役候选池、历史样例还是虚构演示。

目前 LangGraph 调查会把候选和指标证据交给配置的模型；因此在未实现无模型本地分析流程前，不能单独放开 Sportmonks 数据读取并把它包装成“仅本地分析”。模型处理 opt-in 继续作为当前 provider 运行的前置条件。

## Acceptance criteria

- [x] 每种数据模式都有一份集中、类型安全的数据范围说明，明确演示/历史/当前赛季属性。
- [x] 空报告视图展示当前数据源的范围摘要与主要限制。
- [x] 新生成的报告包含数据模式及本次已加载球员记录的赛事/赛季覆盖快照，报告视图展示它；拿不到清单时标明未知；旧浏览器报告可以回退到当前模式描述。
- [x] 文案不声称未知的球员总数、联赛覆盖或授权范围；Sportmonks 说明只覆盖账户已开通且已配置的赛事/赛季。
- [x] 根 `CONTEXT.md`、README、Wayfinder map 和本 issue 保持术语及来源范围一致。
- [x] API/Web TypeScript 编译与网页生产构建通过；未触发真实 provider 请求。

## Comments

- 2026-10-04：依据数据源扩展调查创建。Sportmonks 是现有实现里唯一面向当前赛季的 provider，但真实账户 entitlement 尚未联调；其他非演示来源都是有范围限制的历史数据。
- 2026-10-04：标准与规格审查发现报告需要保存实际加载数据的赛事/赛季清单，且空白视图与缺少覆盖快照的已生成报告需区分。已从球队/候选工具已加载的球员记录生成覆盖快照；没有清单时报告明确说明覆盖范围未知。扩展调查也把旧免费额度标记为待账号核验。两轮审查后未发现相关问题残留。

## Answer

工作台显示各数据模式的时间范围和主要限制；生成报告保留本次已加载球员记录数以及实际赛事/赛季清单，覆盖未知时明确说明。旧报告按其数据模式回退到通用范围描述。没有真实 Sportmonks 账号联调，应用也不会把受限赛事范围表述为完整转会市场。
