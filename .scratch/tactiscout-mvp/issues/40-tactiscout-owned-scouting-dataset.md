# Build a versioned TactiScout scouting dataset

Type: task
Status: claimed
Labels: ready-for-agent
Blocked by: none

## Goal

把项目主线从“接入更多 provider”转为由 TactiScout 自己维护的、可复现且可追溯的球员表现数据集。TactiScout 自建采集/导入、清洗、身份映射、指标计算、版本和质量报告；底层比赛事实仍保留原始来源及其许可。第一方人工观察用于补充战术语境，不要求用户先手工录完整球员库。

## Why now

多个外部来源各有覆盖、条款、身份和指标口径问题，继续增加 provider 不会自动得到可信球员数据库。项目已有 Wyscout CC BY 4.0 历史事件快照和可复现的本地构建管线；下一步应把工作重点放在 TactiScout 自己的版本化数据产品上，用许可及字段口径清楚的公开原始资料构建一个有限候选集。FBref 不再作为抓取底座：Sports Reference 当前条款限制自动采集和替代性数据库用途，其 2026 年 1 月公告也确认上游数据合作终止后移除了高级足球数据。没有找到同时免费、许可清楚、当前、覆盖主要联赛且含细粒度球员能力指标的单一来源，因此 MVP 必须公开真实赛事/赛季边界，不能承诺完整或实时转会市场。

## Scope

- 建立可复现的数据构建流程：固定来源版本/获取日期与许可信息，保留来源 ID，标准化比赛、球队、球员和出场记录，并确定性地计算有定义、分母、样本数和缺失覆盖的派生指标。
- 优先把现有 Wyscout 2017/18 快照作为首个真实统计候选集；StatsBomb Open Data 可用于特别案例，但其 2023/24 德甲清单只有 34 场，不能代表完整联赛候选池。新增来源必须带来清楚的覆盖或指标增益，不能只增加 provider 数量。
- 优先复用第一方观察录入模块作为战术判断补充。观察档位只描述单场主观判断，不跨场自动平均，也不直接折算为适配分；观察数据不得被要求来填补统计来源未提供的数字。
- 记录候选池纳入规则、未覆盖赛事/球员和样本偏差；推荐只能比较快照确实包含且身份与表现证据达到门槛的候选。
- 为每个数据集版本生成来源清单与质量报告，记录来源/采集依据、范围、构建时间、规则与代码版本、输入指纹（适用时）、缺失字段和可复现步骤。
- 对许可明确的事件样本，保留原始 provider ID；每个派生指标记录公式、单位、方向、分母、样本数、字段覆盖和已知代理限制。
- 同一统计字段不可用时保持未知，不用 0 或模型记忆补齐；小样本、位置/职责差异和缺失率进入比较范围说明。
- 用 LangGraph 选择证据工具、识别证据缺口、触发合适追问并复核结论；数据事实和指标计算必须由确定性代码及版本化数据提供。
- 不把批量抓取球探网站或继续接入 provider 当作默认采集方式；公开网页不等于允许批量抓取、长期保存或交给模型。新增来源必须解决一个已定义的数据缺口并有明确采集依据。
- 不得声称覆盖完整当前转会市场或“最新球员能力”。当前球队、身份和赛季信息若来自外部页面，单独标出来源和核验日期；旧比赛表现只说明对应历史样本。

## Acceptance criteria

- 对一份实际公开且许可/协议允许本项目用途的原始比赛数据，可重复构建带版本号和来源清单的球员表现快照；相同输入和规则版本得到相同派生指标，不使用合成球员记录。
- 每个数据集快照包含真实赛事/赛季范围、采集时间、输入指纹、来源许可与署名、构建规则版本、质量报告、缺失覆盖和可复现步骤。
- 第一方观察显示作者、比赛范围、时间点、采集依据和主观/核验状态；没有授权的观察不会进入模型/RAG，且它属于独立的补充证据层。
- 用户可从报告中的任一统计或观察追溯到来源、赛事/赛季、样本、字段定义/量表版本和局限。
- 数据质量摘要可见实际收录的比赛、球员、观察样本、范围及未覆盖指标，不会把缺失数据伪装成 0 或“表现差”。
- 能力比较只在相同采集规程和足够样本的范围内进行；不同来源、不同主观量表或不兼容定义不会被无提示合并。
- 产品清楚区分“第一方比赛观察”“历史统计样本”“当前阵容事实”，不会将前两者包装成现役效力或当前状态。
- README、`CONTEXT.md`、MVP spec 和 issue map 一致描述自建数据集路线及首版历史边界。
