# TactiScout 第一方比赛观察采集规程

## 目的

为球员能力评估补充可追溯的人工战术观察。记录描述观察者在具体比赛中看到的表现，不替代统计候选库、赛事事实、转播追踪数据或完整球员档案；用户无需靠手工录入创建整份候选数据库。

## 单条记录

一条记录对应“一名球员在一场比赛中的观察”。采集时填写：

- 球员姓名；来源 ID 仅在有可靠来源时填写，不按姓名猜测 ID。
- 观察时球队、实际位置与职责；不据此推断该球员当前仍效力该队。
- 赛事、赛季、对阵和观察日期。
- 观察者署名与可核对的参考链接；链接只作为出处，本地应用不自动抓取。
- 优势、风险和具体比赛场景。尽可能记录比赛分钟、对手压力、球员动作和结果。
- 有足够依据时才添加项目定义的 1–5 档维度判断；没有观察到的维度留空。

## 评分约定

1. `1` 表示该场样本中反复暴露明显困难；`2` 表示表现偏弱；`3` 表示表现一般或不稳定；`4` 表示多次展现优势；`5` 表示在多个具体场景中持续突出。
2. 档位只描述该观察者对该场样本的判断。不要跨比赛平均、跨观察者标准化，或把单条档位直接转换成战术适配分。
3. 每个填写的维度都要有具体场景依据。球员名气、印象、模型生成的赛况不能代替观察证据。
4. 机器统计和人工判断分开展示。只有定义了完整事件编码、分母和一致性检查后，才把人工编码事件计数报告为派生统计。

## 建议试点

用“中锋替代者”作为首个垂直切片，与凯恩替代者的产品示例衔接：

- 选择一个赛事和赛季，建立 6 名中锋的封闭观察组；候选身份与观察时球队逐条核实并记录来源日期。
- 每名球员记录 2 场完整比赛样本，共 12 条球员—比赛记录。若只能看片段，明确标为片段样本并记录时间范围，不与完整比赛样本混称。
- 另由第二名观察者独立记录其中 3 条相同样本。先分别完成记录，再对比分歧；展示逐维度完全一致率、相差不超过一档的比例和分歧场景，不用小样本宣称评分信度已经得到验证。
- 根据分歧更新量表说明后，再扩充样本。试点报告只作小样本案例比较，不外推到完整转会市场。

## 产品与数据边界

- 当前工作台的结构化维度为：向前推进、压力下控球、创造机会、无球跑动、压迫参与、防守站位、一对一对抗、攻防转换反应。
- 观察结论必须能回到观察者、比赛样本和具体场景。球员身份、观察时球队和当前效力是不同事实。
- 只有观察者明确授权持久化后才保存在本机；只有另外授权 AI/RAG 处理后才进入 Agent 检索。撤销相应授权时按现有观察记录流程删除或撤出索引。
- 未经授权的转播视频/截图不进入 TactiScout 数据集。项目保存自己的文字观察、时间戳和必要出处链接。
- 人工观察样本不代表整个球员库；小样本只能支持限定范围内的定性案例比较。Wyscout 2017/18 快照仍只用于历史计算和管线验证。
