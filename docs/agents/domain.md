# 领域文档

说明工程技能在探索本项目时，如何读取领域文档。

## 开始探索前读取

- 根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作相关的 ADR

如果这些文件尚不存在，继续工作即可，不要专门报告缺失或提前建议创建。只有在 `/domain-modeling` 实际解决了领域术语或决策时，才按需创建。

## 文件布局

本项目使用单一上下文：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用词汇表中的术语

在 issue 标题、重构建议、假设或测试名称中提到领域概念时，使用 `CONTEXT.md` 定义的词语。不要改用词汇表明确避免的近义词。

如果需要的概念还不在词汇表中，先判断是否正在引入项目未使用的新术语；若确有必要，再通过 `/domain-modeling` 记录。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，明确指出冲突及理由，不要静默覆盖。例如：

> 与 ADR-0007 冲突，但有理由重新讨论，因为……
